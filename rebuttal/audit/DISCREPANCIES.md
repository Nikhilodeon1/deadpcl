# Discrepancies between the submitted paper and the code / data

"Verified" = checked in code or in the raw data by this audit. "Carried" = a
number or statement taken from a file I could read but whose underlying
per-seed outputs are not available locally, so it was not re-derived.
Line references are to files under `deadpcl/` unless noted. Severity is about
how much the item changes what a reader would conclude, not about effort.

| ID | Sev | Paper says | Evidence | Status |
|---|---|---|---|---|
| D1 | High | Task is "per-stay sepsis onset prediction" (Sec. 3). | Label = 1 if any hourly `SepsisLabel` in the first 48 rows is 1 (`src/data/dataset.py:29-30`, `src/data/physionet2019.py:131-134`). Input = the same first 48 hours; the encoder is causal and the head reads the last observed hour (`src/models/backbone.py:93-99, 130-164`). In the raw data, positive kept stays have a median of 10 rows (max 11) at or after their first positive label row (`outputs/g1_physionet_audit.json`). So the label hours themselves are inside the input window. This is detection of an event inside the window, with no stated prediction horizon. All septic records in the files end at most 10 rows after the first positive label, so for about 75% of positive kept stays the read-out hour is the end of the labeled segment (`outputs/g1_septic_truncation.json`). | Verified |
| D2 | High | Confound 1 (label definition) is fixed by re-deriving Sepsis-3 on MIMIC-IV and eICU (Sec. 5.1). | Site A/B labels are the challenge's own hourly labels restricted to the first 48 rows. MIMIC-IV/eICU labels are "Sepsis-3 at any time in the ICU stay", broadcast over all 48 hours (`src/data/mimic4.py:132, 233-235`; `src/data/eicu.py:253, 354-355`; `src/data/sofa_sepsis.py:205-243`). On Site A, 525 of 865 eventually-septic kept stays (60.7%) are labeled 0 because onset is after hour 48. A residual definition mismatch remains between {Site A, Site B} and {MIMIC-IV, eICU}. | Verified (code); external counts carried |
| D3 | Med | Labels use "SOFA scoring anchored to a suspected-infection window" (Sec. 5.1). | Both loaders call the labeler with `mode="single"` (single-point SOFA at the suspicion time) (`mimic4.py:132`, `eicu.py:253`). The window variant is described in code comments as a sensitivity analysis. eICU suspicion is "culture OR an infection diagnosis from a broad list", MIMIC suspicion is antibiotic-culture pairing (`sofa_sepsis.py:68-77, 402-445`). | Verified |
| D4 | Med | The constraint applies "where all variables ... were observed in the raw record" (Sec. 3). | The constraint mask and the masking draws use the observation mask built **after** a 6-hour forward fill (`src/data/preprocessing.py:153-158`; `src/models/backbone.py:279-280`). Raw vs post-fill share of hours with the constraint computable, PhysioNet: Henderson-Hasselbalch 3.04% vs 27.7% (Site A), 0.19% vs 0.56% (Site B); Severinghaus 6.99% vs 26.1% (A), 1.66% vs 8.77% (B). | Verified |
| D5 | Med | Loss is `L = L_mask + lambda * L_phys` (Sec. 3). | The optimized loss is `L_mask + lambda * (L_phys * r)` where `r` is an EMA of `min(20, L_mask / L_phys)` (`src/training/train_utils.py:12-50, 215`). The effective weight is lambda times a quantity that tracks L_mask, capped at 20x. | Verified |
| D6 | High | Lambda is chosen by best source-validation AUROC over six values (Sec. 5.3, 6). | `config.py:41-46` says the default lambda (0.5) was "selected on Site B as a held-out validation domain". Sweep numbers from the sibling selection-criteria project's figure script (seed 42, lambda = 0, 0.1, 0.5, 1, 2, 5): source-validation AUROC 0.8350, 0.8306, 0.8249, 0.8271, 0.8203, 0.8280, so source validation would pick lambda = 0, not a constrained model. Which lambda the submitted PCL row used cannot be determined from the files available. | Verified (config); sweep carried |
| D7 | Low | Warmup is 40% (corrected), 30% (original). | Function default is 0.3 (`train_utils.py:188`); a config comment says 0.4 is passed by the driver (`config.py:53`). The driver is not available. | Unresolved |
| D8 | High | PhysioNet "reconstructs [PaO2] from oxygen saturation by inverting the Severinghaus equation" (Sec. 5.4). | The raw files have no PaO2 column (41-column header; 0 of 40,336 files). The reconstruction is done by this repo's loader (`physionet2019.py:47-55`) with `cbrt(23400*S/(1-S))`, which drops the `150*PaO2` term, so it is an approximate inverse of the loss's forward function, not an exact one. It applies at 7.29% (A) and 1.94% (B) of hours. At MIMIC-IV and eICU PaO2 is a measured blood-gas value (`src/data/variables.py:79, 126`). The variable means different things at source and target. | Verified |
| D9 | High | "A companion audit across five site-pair comparisons found [the composition ratio] exceeds 1.0 on four of the five" (Sec. 5.5). | The five values (1.266, 1.157, 1.120, 1.414, 0.371) are in the detector project's log (`reboot/detectors/logs/full5.out:18-22`) and are validation scenarios (three ablated-copy controls, an eICU split, PhysioNet Site A compared with itself), not site pairs. The real Site A vs B value is about 0.27 and MIMIC-IV vs eICU is 0.198 (not scored). A ratio of 1.414 for a site compared with itself shows the ratio is unstable when its denominator is near zero. The sentence in the submitted paper is wrong. | Verified (log); ratios carried |
